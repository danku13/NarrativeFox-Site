# NarrativeFox Site

Посадочная страница NarrativeFox: контент-маркетинг для B2B без целого отдела.

Система ИИ-агентов превращает голосовые сообщения, заметки и документы в
стратегию, публикации для разных площадок и регулярный разбор отклика. Тексты
и ключевые решения утверждает человек.

- Домен: <https://narrativefox.tech>

## Стек

- Next.js 16 (App Router, Turbopack): серверная сборка `output: "standalone"`
  или статический экспорт `output: "export"` для GitHub Pages
- React 19
- Tailwind CSS 4
- shadcn/ui (Radix UI)
- Prisma + SQLite (хранение заявок; только в серверной сборке)
- Шрифты: Manrope (заголовки) и Inter (основной текст), оба с кириллицей

## Разработка

```bash
bun install
cp .env.example .env     # путь к SQLite-базе
bun run db:push          # создать базу по схеме Prisma
bun run dev              # http://localhost:3000
```

Проверка кода: `bun run lint`, `bunx tsc --noEmit`.

## Продакшен

bun run build   # next build + сборка standalone в .next/standalone

## Деплой на GitHub Pages

Публикация автоматическая: воркфлоу `.github/workflows/deploy-pages.yml`
собирает статический экспорт (`out/`) и выкладывает его через
actions/deploy-pages на каждый пуш в `main`, на релиз и по ручному
запуску (вкладка Actions → Run workflow).

Однократная настройка репозитория:

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Домен `narrativefox.tech` уже привязан: A-записи DNS указывают на
   GitHub, а `CNAME` в корне копируется в артефакт сборки, чтобы привязка
   не слетела. После первого деплоя там же включить Enforce HTTPS.

Чем статическая сборка отличается от серверной:

- параметры страниц (`?for=`, `?role=`, `?contour=`) читаются на клиенте,
  все страницы предрендерены;
- API заявок `src/app/api/leads` в статическую сборку не входит (воркфлоу
  исключает каталог только внутри CI-чекoutа), серверная сборка
  собирает его как раньше;
- `NEXT_BASE_PATH` задаётся только для хостинга вида
  `user.github.io/repo`; на кастомном домене сайт живёт в корне и путь
  не нужен.

Локальная проверка статики:

```bash
mv src/app/api /tmp/api-backup        # API не входит в статическую сборку
NEXT_OUTPUT=export NEXT_PUBLIC_STATIC_EXPORT=1 bun run build:static
mv /tmp/api-backup src/app/api
python3 -m http.server 8000 -d out    # http://localhost:8000
```

## Форма заявок и антиспам

Единственный канал связи на странице: короткая форма, без публичной почты и
личных контактов.

Серверная сборка, защита без капчи (`src/app/api/leads/route.ts`):

- honeypot-поле `website`, скрытое от людей;
- временная ловушка: форма, отправленная быстрее чем через 3 секунды, отклоняется;
- лимит частоты: не больше 3 отправок в минуту с одного IP;
- серверная валидация длины всех полей;
- заявки пишутся в SQLite через Prisma (модель `Lead` в `prisma/schema.prisma`).

Статическая сборка (GitHub Pages): своего сервера нет, приёмник ищется
в таком порядке, обе настройки живут в переменных репозитория
(Settings → Secrets and variables → Actions → Variables):

1. `LEAD_ENDPOINT`: URL внешнего API с тем же контрактом, что у
   `/api/leads` (например, отдельный деплой серверной сборки);
2. `LEAD_EMAIL`: заявка собирается в письмо и открывается
   в почтовом клиенте посетителя;
3. без переменных форма честно сообщает, что приём заявок ещё
   не подключён (событие `nf_lead_unavailable` в dataLayer).

Honeypot работает в обоих режимах.

## SEO и домен

- `metadataBase`, canonical, Open Graph (og:image 1200×630 — `public/og.png`),
  Twitter Card, JSON-LD `Organization` — в `src/app/layout.tsx`
- `src/app/sitemap.ts` → `/sitemap.xml`; `public/robots.txt` ссылается на него
- `src/app/apple-icon.png` (180×180) и `src/app/icon.svg` — фавиконы
- Все абсолютные URL ведут на `https://narrativefox.tech` (константа
  `SITE_URL` в `src/app/layout.tsx`)
- `CNAME` в корне привязывает домен `narrativefox.tech`

### Подключение домена (Vercel)

1. Импортировать репозиторий в проект Vercel (Next.js подхватится нативно).
2. Settings → Domains → добавить `narrativefox.tech` и `www.narrativefox.tech`.
3. В панели DNS у регистратора вместо парковки поставить:
   - `A`-запись `@` → `76.76.21.21`
   - `CNAME` `www` → `cname.vercel-dns.com`
   (точные значения Vercel покажет при добавлении домена)
4. Дождаться сертификата и www-редиректа (Vercel делает сам).

Для SQLite на серверлесс-хостинге подключить внешнюю базу (Turso, PlanetScale)
или деплоить на своей ноде через `bun run start`.

## Редакционные правила проекта

- Тексты на живом русском: без кальки с английского и «переводных» оборотов.
- Без длинных тире в текстах страницы.
- Один основной призыв к действию («Обсудить пилот»), без конкурирующих кнопок.
- Обещания формулируются как проверяемый план, а не как типичный результат.
- Пример показан на собственном материале: каналы NarrativeFox ведёт сама система.

## История изменений

**Ноябрь 2026, публикация на GitHub Pages.** Сайт научился собираться
статическим экспортом и публиковаться автоматически: воркфлоу
deploy-pages выкладывает `out/` на каждый пуш в main и на релизы.
Параметры страниц переехали на клиент, форма в статике ищет внешний
приёмник или почтовый клиент, серверная сборка не изменилась.

**Ноябрь 2026, язык клиента.** Слово «интервью» ушло со всех поверхностей: вход
системы описан словами клиента (голосовые сообщения, заметки, документы,
таблицы). Плашка-дисклеймер примера удалена, честность сохранена одной фразой
в лиде о собственных каналах. Мокап первого шага показывает несколько коротких
голосовых вместо одного длинного трека. Метрики hero, метаданные и README
приведены в соответствие.

**Ноябрь 2026, переработка структуры.** Первый экран перестроен вокруг задачи
клиента («Контент-маркетинг для B2B без целого отдела»), добавлен сквозной
пример из 6 шагов с артефактами системы, конкретизирован состав пилота,
появились ответы на вопросы о данных, доступах и правах. Личные контакты
заменены защищённой формой заявки (Prisma + SQLite, антиспам без капчи).
Тексты прошли вычитку на живой русский.

**Ноябрь 2026, раунд валидации.** Лендинг прошли ревью 9 ролей (CMO, PMM, SMM,
владелец малого бизнеса, архитектор, эксперт по агентной разработке, техлид,
TPM, Head of Product) с фокусом на рынок РФ: переформулированы заголовки,
добавлен блок об отличии от «текста из нейросети», унифицированы термины и
цифры, честная экономика вместо обещаний, технический SEO-пакет (og:image,
canonical, sitemap, JSON-LD, WCAG AA).
